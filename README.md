# 오늘도 덥습니다 ☀️

폭염주의보·폭염경보 발령을 자동으로 감지해 **Mattermost 채널에 더위 안전 카드**를 올리는 캠페인 봇입니다.

```
[GitHub Actions · 매일 아침 9시(KST)]
        │
        ├─▶ 기상청 기상특보 API   ──▶ 발표·해제 이력 재생 → 지금 발효 중인 폭염 특보
        └─▶ 기상청 단기예보 API   ──▶ 카드에 얹을 오늘 최고/최저기온
                    │
                    ▼
        [하루 1회 중복 필터] ──▶ Mattermost Incoming Webhook ──▶ 메시지 카드
```

알림은 **폭염 특보가 실제로 발효 중이거나 최근 24시간 내 해제됐을 때만** 나갑니다.
기온이 높다는 이유만으로는 보내지 않고, 특보가 없는 날은 조용합니다.

## 준비물

### 1. 기상청 API 키

[공공데이터포털](https://www.data.go.kr/data/15000415/openapi.do)에서 아래 두 개를 활용신청합니다.

- 기상청_기상특보 조회서비스 (감지)
- 기상청_단기예보 조회서비스 (카드에 표시할 기온)

마이페이지에서 **일반 인증키(Decoding)** 를 복사합니다.
Encoding 키를 쓰면 이중 인코딩되어 실패하니 주의하세요.

### 2. Mattermost Incoming Webhook

통합 기능(Integrations) → Incoming Webhook → 채널 선택 → URL 복사.

## 로컬 실행

```bash
pip install -r requirements.txt
cp .env.example .env   # 값 채우기
```

```bash
python main.py --demo
```

API 호출 없이 카드 모양만 미리 봅니다. 실제 조회는 아래처럼 합니다.

```bash
python main.py --dry-run
```

전송 없이 감지 결과와 페이로드만 출력합니다. 이상 없으면 그냥 `python main.py`.

| 옵션 | 설명 |
|---|---|
| `--demo` | API 없이 샘플 카드 출력 |
| `--dry-run` | 실제 조회하되 전송은 안 함 |
| `--force` | 중복 방지 무시하고 다시 보냄 (디자인 확인용) |

응답 원본을 확인하고 싶으면:

```bash
python probe.py warn
```

## GitHub Actions 설정

레포 **Settings → Secrets and variables → Actions** 에 두 개를 등록합니다.

| 이름 | 값 |
|---|---|
| `KMA_SERVICE_KEY` | 공공데이터포털 일반 인증키(Decoding) |
| `MM_WEBHOOK_URL` | Mattermost Webhook URL |

등록 후 Actions 탭에서 `오늘도 덥습니다` → **Run workflow** → 모드를 고르고 실행합니다.

| 모드 | 하는 일 |
|---|---|
| `dry-run` | 감지만 하고 전송하지 않음 (기본값) |
| `send` | 실제 발송 |
| `probe` | 기상청 원본 응답을 로그에 출력 |

스케줄 실행은 항상 `send`입니다.

## 지역 변경

[src/config.py](src/config.py)의 `REGIONS`만 고치면 됩니다.

```python
Region(name="서울", stn_id="108", nx=61, ny=125)
```

- `nx`, `ny`: 단기예보 격자 좌표. **동 단위로 정확합니다.** 위 값은 역삼동입니다.
- `stn_id`: 특보 발표관서 코드(`108`=서울, `133`=대전, `159`=부산 …).
- `name`: 카드에 표시할 이름.

여러 지역을 넣으면 각각 따로 감지해 카드를 만듭니다.

### 기온과 특보의 정밀도가 다릅니다

기온은 격자 좌표라 **역삼동 단위**로 정확하지만, 특보는 `stnId` 단위로만 조회됩니다.
특보 제목에 지역명이 전혀 없어서(아래 참고) 서울 안에서 강남구만 골라낼 방법이 없습니다.
그래서 카드의 지역 표시는 실제 특보 범위에 맞춰 `서울`로 두었습니다.

## 특보 제목 파싱

실제 응답은 이렇게 옵니다.

```
[특보] 제07-100호 : 2026.07.29.10:00 / 폭염경보 변경 (*)
[특보] 제07-92호  : 2026.07.24.16:00 / 폭염주의보 변경·폭염주의보 해제·열대야주의보 발표 (*)
```

- **지역명이 없습니다.** 지역은 `stnId`로만 구분됩니다.
- 한 건에 여러 특보가 가운뎃점(`·`)으로 묶여 옵니다.
- 동작은 `발표` / `변경` / `대치` / `연장` / `해제` 입니다.

`current_warnings()`가 발표 이력을 시간순으로 재생해 지금 발효 중인 특보를 남깁니다.
`해제`면 지우고, 나머지 동작이면 발효로 봅니다.

응답 형식이 바뀌면 `probe` 모드로 원본을 확인한 뒤 [src/detector.py](src/detector.py)의
`SEGMENT` 정규식을 조정하세요.

## 중복 발송 방지

특보는 며칠씩 이어지므로 매일 아침 같은 특보가 다시 잡힙니다.
중복 방지 키에 **날짜를 포함**시켜, 발효가 이어져도 **하루에 한 번만** 카드가 올라갑니다.
키는 `state/sent.json`에 남고 Actions가 이 파일을 레포에 다시 커밋해 실행 사이에 상태를 유지합니다.
7일이 지난 키는 자동으로 정리됩니다.

## 알려진 제약

- **GitHub Actions cron은 정시에 실행되지 않습니다.** 부하에 따라 수 분~수십 분 밀립니다.
  9시 정각이 중요하면 상시 구동 서버의 cron으로 옮기세요.
- 특보 조회는 **오늘 기준 6일 전까지만** 가능합니다(초과 시 `resultCode 99`).
  6일보다 오래 전에 발표되어 아직 발효 중인 특보는 놓칩니다.
- 서울 안에서 구 단위로 특보를 좁힐 수 없습니다(위 참고).
- 아침 9시 실행 시점에는 오늘의 `TMN`(최저기온)이 이미 지나 예보에서 빠질 수 있습니다.
  그 경우 카드에 최저기온 필드가 생략됩니다.

## 열대야에 대해

열대야는 **정식 기상특보로 존재합니다**(`열대야주의보 발표` / `열대야주의보 해제`).
이 캠페인은 폭염에 집중하기로 해서 `SEGMENT` 정규식에서 의도적으로 제외했습니다.
포함하려면 정규식을 `(폭염|열대야)(주의보|경보)` 로 넓히고
[src/card.py](src/card.py)의 `COLORS` / `ICONS` / `ACTION_GUIDE`에 항목을 추가하면 됩니다.
